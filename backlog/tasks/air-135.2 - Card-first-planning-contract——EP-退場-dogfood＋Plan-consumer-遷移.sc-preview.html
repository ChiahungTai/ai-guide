訂「東西寫在哪一格」——計畫、決策、證據在卡上的住處規則＋EP 正式退場。所有卡的基礎。

住處規則

  • Description／AC＝intent／constraint／outcome；Plan＝可修訂 working hypothesis（非 trivial 改案必留 supersedes＋reason）；Notes＝evidence；Final Summary＝結算
  • intent verbatim 與 non-goals 經 user 開頭交代即凍結，修訂只能 append supersedes
  • 跨 task 長壽決策用 decision entity（schema 容納 rejected alternatives）；單卡修訂理由用 Notes——防 Notes 成第二真相源
  • belief 儲存＝假設台帳（穩定 id＋unverified/verified/invalidated 狀態機，推翻 append evidence 禁改寫）＋decision entity 選填 invalidates／affected／confidence；觸發歸 135.7、時序歸 135.3

EP 退場

  • Backlog Task 原生 sections＋nested tree 已堪 plan of record——standalone EP 無預設存在理由（11 弧 187 sections 抽樣：零個不可由卡表達的 primitive）
  • consumer 未遷完不宣告全域退役；不可表達 primitive 才留窄例外＋reversal condition

開卡＝Description 先行（人話＋一張 mermaid 圖），user 在 SC ext 點卡確認後才建卡、再補 AC/Plan。

Acceptance Criteria

☐ #1 抽樣最近 5–10 個 full-tier arc，列出 EP 各 section 實際被 implement/review/verify/continuation 消費與未消費比例；將內容映射到 card section／decision／supporting doc，找出是否存在真的不可表達 primitive。抽樣判準＝「能否由卡恢復意圖與共同理解」，非 EP 使用量統計；sample 結果投影到 Code Lens（非文字研究報告）；**以既有 P2 POC（7 EP／122 sections）為種子樣本補抽至 5–10 arcs**；consumer 與映射盤點以「讀 EP 的 code path」為界，不升級成全面 tool audit
☐ #2 AIR-135 family 不建立 standalone EP 也能由 fresh session/worker 從 parent＋sub-card 還原 intent、accepted constraints、current plan、plan revision reasons、scope、verification contract 與 evidence；還原範圍必須涵蓋 Two-Touch entry 六欄與 exit 終場 receipt pointer，缺任一必要欄位留 residue；**還原清單須含 priced-autonomy 契約欄位：revert 預算（含餘額）／預授權類／假設台帳狀態／成功謂詞——fresh worker 缺任一欄不得開工**（缺欄位的 worker 只能以打斷或超支收場）；失敗要留下可重現 residue
☐ #3 定義 card-first section contract：Description/AC 承載 intent/constraint/outcome contract；Plan＝可修訂 working hypothesis；Notes/comments＝evidence/decision/revision rationale；Final Summary＝settled outcome。非 trivial plan replace 必記 supersedes + reason/evidence。**存儲分配**：entry 六欄——intent verbatim＋成功謂詞住 Description／AC（謂詞進 AC 可驗收），non-goals＋revert 預算＋預授權類住 AC 約束區，假設台帳住 Plan 首節（slice 邊界審計由 135.1／135.7 執行，本卡只給住處）；**intent verbatim 與 non-goals 一經 user 開頭交代即凍結，LLM 修訂只能 append supersedes＋reason、禁改寫原文**（intent-diff 防拉伸的基線）；exit 終場六塊——receipt＋intent-diff＋決策紀錄住 Final Summary，被拒選項＋待決事項同步進 decision entity／pending-decision 台帳（只記 pointer，不複製內文）。卡面 Description／AC／deps 須保持機械可投影（M1 ephemeral 投影源），**結構化契約欄位（六欄、預算、預授權、謂詞）禁以自由散文承載**。decision entity vs Notes 分工：跨 task 長壽 decision 用 Backlog decision entity；單卡內 plan revision rationale 用 Notes supersedes＋reason／evidence；discussion projection、decision ledger、revision history、evidence pointer 的 ownership 由此條定義，防 Notes 成第二真相源；**終場六塊 settled 落點細節**：comprehension receipt→Final Summary、決策紀錄（含被拒選項）→decision entity（schema 須容納 rejected alternatives）、no-impact 機械證據→Notes pointers、intent-diff→revision rationale；pending-decision 台帳只持未決項，user 裁決後經 AC#6 回寫路徑落卡，台帳不成第二 decision truth。**belief 儲存＝Epistemic Merge 最小閉環（0919 外部收割——雙腿一致歸本卡）：假設台帳列帶穩定 id＋狀態機（unverified／verified／invalidated），推翻＝append evidence pointer＋supersedes（同 intent verbatim 紀律禁改寫原文；invalidated row 標記不刪除——供 Intent v2 考古）；未驗證列＝開頭交代的不確定性 surfacing（UNCERTAINTIES 不另設欄，防同物第二住處）；decision entity 選填 `invalidates:`（assumption／decision id 清單）＋`affected:`（卡指針）＋`confidence`（一詞）——belief-update 型 decision 沿用既有 Context/Decision/Consequences/Rejected Alternatives 段式（decision-4 實證容得下），Affected 指針不可解＝fail-loud residue；Intent v1→v2 變更走同語彙（invalidates cascade 不另立機制）；觸發義務歸 135.7 AC#7（裁決後 Marshal 單一寫入）、時序語義歸 135.3（Verify exit／Settle 迴圈）**
