## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
重新定義開發流程的 semantic model，而不是把現行 commands/skills 逐一升格成 lifecycle nodes。候選骨架＝entry Align → Shape/Plan → Build → Verify → exit Align → Settle；要用實際 session evidence 檢查 merge/split、entry/exit predicate 與是否需要不同命名。Marshal 是包覆全弧的 orchestration responsibility，不是 node；WT/session/model routing/retry/bridge/handoff（同 repo）等 mechanics 不出現在 human mental model。同步評估「AI lifecycle」是否改名為 Development Arc / AI Development Arc，並產現行 command→semantic obligation mapping，讓既有 skill 可作 strategy 而非流程真相源。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 用近期真實開發 session audit 對每個候選 node 做必要性驗證；每個 node 都能回答人/LLM在此刻必須共同知道什麼、exit evidence 是什麼，不能只因現有 command 存在而保留
- [ ] #2 Align 被定義成 human shared-understanding obligation：entry 驗 intent/non-goal/boundary，exit 驗 actual code reality/outcome；具體 viewport 可條件式選擇，不把 artifact production 當 comprehension
- [ ] #3 Verify 明確區分 machine verification 與 independent judgment/review 的責任，即使最後 UI 顯示為同一 phase，也不能失去 independence axis
- [ ] #4 Marshal-owned mechanics 清單與 cross-repo boundary 清單明確；同 repo handoff/WT/session rollover 不再成 lifecycle node
- [ ] #5 產出名稱裁決與 migration map：現有 /spec、execution-plan、implement、post-build、commit、handoff、viewport skills 各自映射到 obligation/strategy/transport 哪一層
- [ ] #6 Marshal 擁有 phase transition 驅動：在既有授權與 evidence predicate 滿足時自動推進 Shape/Plan→Build→Verify→exit Align→Settle，不要求 user 逐段召喚 workflow command；只有 authority／方向／取捨等真正 human gate 才停下，並明示 pending decision
- [ ] #7 exit Align 的最低交付是 plain-language comprehension receipt：實際做了什麼、和原 intent 是否一致、主要 evidence、尚未驗證／殘留、需要 user 決定什麼；圖／tour／Report Shell 依 task/risk 選用，不能用大量 artifact 取代共同理解
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
【0918 authority 邊界】AC#6 的「既有授權」以 repo 既有紀律為單一源，本卡不重定義紅線清單：outward action（commit、跨 WT、跨 repo 回寫、外部寫入、刪共享資料）Marshal 恆停並明示 pending decision；紅線／黃線分級沿 outward-action-consent rule＋autonomous-execution skill；自主推進僅限授權面內 evidence predicate 滿足處。
