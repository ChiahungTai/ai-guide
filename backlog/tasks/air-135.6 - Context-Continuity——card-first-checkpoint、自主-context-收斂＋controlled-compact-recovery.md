## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
斷了怎麼接——Context Continuity 的 correctness 建立在「持續外部化＋可驗證恢復」，不依賴任何 harness 的 compact trigger（0922 VETO 實證：ZCode 無 compact-moment trigger——判決全文見 AIR-155 卡 Notes「0922 gate 判決」）。

**Canonical state（card-first）**

- workflow 採 card-first（AIR-135.2）：task/card 持 intent／AC／current plan／revision rationale／accepted decisions；full tier 才由 EP 持詳細 execution plan；WT/git、tests、review findings、artifacts、job/liveness 各由既有 owner 持有。
- continuity 層只保存 pointer 與無法可靠重建的 verbatim residue；禁第二 workflow DB。

**持續 checkpoint（正典；AIR-155 機制件為唯一實現）**

- 工作中每次實質進展後，durable owner＋AIR-155 checkpoint 保持可接續；semantic boundary（accepted decision/correction、non-trivial plan revision、phase transition、commit/settle、job terminal collection、重要 failure/root-cause、長輸出 work-unit 邊界）是**最低更新點／稽核下限**，不是觸發依賴。
- checkpoint 機械契約（四問＋restore-proven＋cleanup guard）單一源＝`scripts/compact_checkpoint.py`＋`hooks/compact-restore-inject.py`；workflow 可附 decisions／evidence／per-WT state／job pointers／read-set／unrecovered scope 等額外欄位；內容語義定義源＝[task-recovery](../../skills/_common/task-recovery.md) 寫入端欄位表。
- 135.7 job/liveness 真相只留指針，不複製。

**壓力／中斷前：thin continuation packet（on-demand transient projection，非常駐）**

- packet＝canonical state 的 delta 投影：identity＋per-WT git state（owning WT 與 canonical WT 分列）＋artifact paths（實際路徑）＋last_verified_checkpoint{path,sha256}＋since-checkpoint delta＋pending 決策（引台帳）＋active jobs（引 135.7 台帳）＋next action＋minimal read-set＋unrecovered scope；錨不符 fail-closed 從卡樹重建。
- packet **引用** checkpoint、不複製不包含；禁常駐檔、禁 generation registry、禁 cleanup lifecycle；永不直發跨 repo（外發升格 outward，走 AIR-135.5 gate）。

**恢復（adaptive rehydration）**

- 先驗實物（WT/git/runtime/artifacts/jobs）再相信 checkpoint；驗證通過才寫 restore-proven；缺口只擴受影響 read-set，不重灌整卷、不重做已完成工作。
- compact summary／舊 conversation／memory 只當 hint/routing aid，禁覆蓋當前 card／WT／runtime facts。

**Harness boundary**

- correctness 不要求 programmatic compact；可控 context clearing 主路徑＝**fresh-session epoch**（一弧一 session；ZCode 黑盒下唯一可控邊界）。
- muse exec（`--context-compaction-strategy`／threshold）與 codex（app-server `thread/compact/start`）為 capability-specific adapter——capability-gated 口吻記載，不進主路徑、不寫死接線。
- 本卡不自製 summarizer／token GC；LLM 不能自行刪除已進 window 的 token；/compact 與 fresh-session 時機裁決留在 user，Marshal 只持續保存＋報告 context pressure。

  CK["持續回寫 durable owner<br/>card-first checkpoint"] --> PK["壓力/中斷前<br/>thin packet（delta 投影·on-demand）"]
  PK --> RH["adaptive rehydrate<br/>先驗實物→restore-proven"]
  RH --> RS["resume 下一動<br/>不重做已完成"]
  RS -.->|"下一個 boundary"| CK
