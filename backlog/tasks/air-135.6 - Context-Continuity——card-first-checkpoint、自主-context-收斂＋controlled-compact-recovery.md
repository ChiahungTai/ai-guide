## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
把 context 管理從「快滿了才跑 compact-prep」改成 Development Arc 的持續可靠性機制：平時在有意義的 semantic boundary 把 durable state 回寫 card／evidence，維持隨時可中斷、可重建；context 壓力出現時只投影薄的 continuation packet＋delta，compact／fresh session 後從 canonical card state 與實物做最小 read-set 恢復。這不是自製 summarizer，也不讓 AI 取代 user 決定何時呼叫 harness /compact；目標是降低對自動 compact 的依賴，讓 compact 即使發生也只是 transport boundary，而不是任務狀態唯一保存點。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 定義 Context Continuity contract：區分 durable task state、ephemeral continuation packet、harness compact 三層；不開發自製 summarizer／token GC，不把 /compact 或 fresh-session decision 從 user 手上拿走；Marshal 可主動保存狀態與報告 context pressure，但無既有授權不得自行觸發 compact/new session
- [ ] #2 card-first canonical owner：intent／AC／current plan／revision rationale／accepted decisions 住 parent/sub-card；WT/git、tests、review、artifacts、job receipts 由各自 owner 持有。continuation packet 只存 identity＋pointer＋必要 delta／verbatim residue，不複製整份 truth，也不要求 standalone EP
- [ ] #3 建立 event-driven checkpoint policy：至少在 accepted decision/correction、non-trivial plan revision、phase transition、background job terminal collection、重要 failure/root-cause、長/高輸出 work-unit 邊界更新 durable state；禁止每個 tool call 都寫流水帳。checkpoint 必須足以回答 current phase、verified/unverified、pending jobs/decisions、next executable action。**弧執行中 Marshal 按本政策回寫 card／artifact checkpoint 屬任務授權內含，不逐次打斷請示（Two-Touch 不變式①；可逆＋人可見）——除外：跨 repo sent-record 的寫入（發送痕）走 AIR-135.5 AC#6 確認 gate，不在此預授權內**。job terminal／active job 面的 liveness 真相以 AIR-135.7 台帳為準，本卡只消費其 contract，不另存 job 狀態
- [ ] #4 context 壓力或即將中斷時，Marshal 從最新 canonical state 產 thin continuation packet：task/arc identity、owning WT、last verified checkpoint、since-checkpoint delta、pending human decision、active job/collector、next action、minimal read-set、unrecovered scope；優先引用 card/artifact 而非掃全 transcript，只有 canonical state 明顯缺口才 fallback 做全-session preserve extraction——**fallback 產物只當 hint／routing aid（與 AC#7 compact summary 同級），採用前須按 AC#5 先驗 WT／git／runtime／artifacts 實物**。**continuation packet 與 AIR-135.5 AC#6 通知草案禁混用**：packet 屬弧內恢復投影，永不直接作為跨 repo 發送草案；需通知時須重走 135.5 組裝＋逐次確認 gate。欄位映射：packet 專有＝owning WT（含 per-WT git state）／minimal read-set／unrecovered scope；draft 專有＝target／expected response type／correlation id／expiry；共享＝identity／artifact pointers＋hash／context delta（引用同一 owner，不複製）
- [ ] #5 恢復採 adaptive rehydration：先 card/TaskRef → 核對實際 WT/git/runtime/artifacts/jobs → active findings/evidence → 只讀下一動所需 guidance；先驗實物再相信 checkpoint。缺口只擴大受影響 read-set，不為『恢復完整記憶』重灌整卷或重跑已完成工作
- [ ] #6 context-budget discipline 與 AIR-135.1 接軌：大輸出 artifact-first、探索/廣域查證優先 delegated bounded slices、回主座席只收 bounded receipt；重複穩定材料以 pointer/read-set 消費，不在每次 dispatch 重貼。這些降低未來 context 增長，但不宣稱模型能自行刪除已進 window 的 token
- [ ] #7 compact boundary 可追溯：continuation/checkpoint 有 generation 或 previous-checkpoint pointer；若 harness 自動 compact、手動 /compact、quota death、session restart 任一發生，都能從同一 durable owner 恢復；compact summary 只當 hint/routing aid，不當 completion/decision/evidence 真相源。恢復所需未回收清單的閱讀面由 AIR-135.7 sweep／主 session 派生（卡面只放指針）
- [ ] #8 遷移現行 compact-prep／task-recovery：compact-prep 從『每次先掃全 session 造主摘要』降為 boundary adapter/fallback；task-recovery 的 durable owner 優先序改成 card-first（EP 僅 legacy/exception consumer）；保留 verbatim error/finding residue 與 hook 可用時的 raw-tail 補充，不新增 active-pointer registry
- [ ] #9 dogfood 至少一條 AIR-135 長弧：在累積大量 context 後做 checkpoint，再用 fresh context/模擬 compact 後只給 TaskRef＋continuation pointer，能正確辨識 current plan、owning WT、已驗/未驗、active jobs、下一動且不重做已完成 work；記錄所需 read-set 與失敗 residue。MVP 定序：先手動跑 schema＋慣例（checkpoint 四問＋packet 欄位＋135.7 liveness MVP 登記／sink 驗收），工具化（掃描／組裝輔助）須待本 AC dogfood 出現重複手工負載或恢復失敗證據後再議

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
〔baseline：ai-guide c0ae0de7〕

〔已決策勿重辯〕
① harness compact 是 runtime transport/lifecycle black box；本卡不做自製 summarizer、token GC 或假裝 LLM 能直接刪除已進 context 的 token。
② user 保留 compact／fresh-session 時機裁決；Marshal 的自主範圍是持續保存、context pressure 告知、checkpoint/materialization 與可驗證恢復，不是未授權地自行 /compact。
③ canonical state 採 AIR-135.2 card-first；continuation packet 是 derived projection，不能成第二 workflow DB。
④ checkpoint 事件驅動而非逐工具流水；優先引用現有 owner，verbatim residue 只保存不可可靠重建部分。
⑤ recovery 以實物驗證＋adaptive read-set 為核心；compact summary、memory、舊 checkpoint 都不能覆蓋當前 card/WT/runtime facts。

〔研究依據〕
- 2026-09-15 codex compact architecture：local/remote/token-budget 三路共用 compact lifecycle，harness 自己擁有 replacement/window/checkpoint；我們可借鏡的是 pre/post boundary、generation、routing summary，不應重造本體。
- controlled-compact-strategy：checkpoint 應保存 objective/decisions/constraints/current/pending/next，resume 要驗證能否繼續下一 action，而非只背摘要。
- compact-direction-handoff：已收斂為『先保存任務、user 決定 compact、恢復後驗實物』；不要 custom summarizer/registry；Marshal 狀態需在 caller 可讀 artifact。
- memory-mechanism-analysis §6：現行缺口包含 incremental checkpoint、semantic boundary、artifact index/window chain；但舊結論『incremental checkpoint 無施力點』是針對 harness 內 compaction，本卡做的是 workflow-level durable checkpoint，不改 harness。
- archived 09-08 feedback：compact 時機屬 user judgment；接續品質才是 AI workflow 的責任。此 invariant 保留。

〔實作範圍〕
A. 定 checkpoint schema/semantic trigger 與 card/artifact pointer 規則。
B. 定 thin continuation packet/generation/delta 格式與 fallback 全-session extraction 條件。
C. 把 recovery owner/read-set 從 EP-first 遷到 card-first，定 drift 驗證。
D. 與 AIR-135.1 Arc compiler 對接 checkpoint obligation、bounded dispatch/context-budget receipts。
E. 改造 compact-prep 為 boundary adapter/fallback，保留 harness-specific hook 差異。
F. 做 fresh-context dogfood + failure injection；量測重讀量/重工/漏 pending，而非只看摘要字數。

〔介面 ownership〕checkpoint obligation／continuation packet／context-delivery budget 的 schema 由本卡擁有並先行定義；AIR-135.7 為消費方與義務定義者（經其 DispatchSlice 契約要求 AIR-135.1 compiler 編入），三方不雙向等待——135.7 AC#5 的對接指消費本卡 schema，非共同設計門檻。**continuation packet 本身非 outward**（弧內使用免發送 gate）；一旦用作跨 repo 發送載荷即升格為 outward，須重走 AIR-135.5 AC#6 草案 schema＋逐次授權，禁直發。0919 直接 commit 委任不及於任何跨 repo 寫入（含 packet 外發）。
