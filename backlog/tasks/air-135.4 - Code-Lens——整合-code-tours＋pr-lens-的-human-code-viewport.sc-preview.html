Acceptance Criteria

☐ #1 定義 canonical fact layer 與 derived view layer：任何 Code Lens 輸出都可追溯 card/repo facts，view 本身不成 authoritative planning/workflow state。**視圖須由 generator 從 canonical facts 機械投影（禁手抄——P9 v1 漂移實證），每份輸出帶 provenance sidecar＋新鮮度錨（stale 自稱 stale）**
☐ #2 code tour 與 pr-lens 共用一份最小 projection contract；同一 change 可切 narrative 與 topology/impact 視角，不重算／複製彼此已有的 core facts。**M1 卡內容視圖（0919 v4 終版）＝SC ext 點卡預覽：卡本身即投影（Description 人話＋一張 mermaid 圖）；視圖五塊語義——解什麼／定什麼契約／不做什麼＋承接上游（direct deps 深度=1、transitive 只計數＋drill-down）／影響＋現況（機械算）／待裁決（pending pointers）——全部由 canonical 卡面機械可達（禁手抄、禁爬 transitive 鏈、禁 projection-on-projection）。事實協商中禁 code-fact 圖。Code Lens view mapping 須標 Development Arc node 與觸發時刻：entry Align 顯示卡內容；Shape exit 顯示 SPEC／計畫；exit Align 顯示終場 receipt、intent-diff、decision、否決介面**
☐ #3 viewport 選型＝manual-first：先交付生命週期手冊式選型指南（①開工前 Impact／Architecture 預判——改動未發生即可查 ②計畫討論不用 pr-lens：口述＋輕量 mermaid，事實協商中 ③執行中不產 Lens 視圖：活的面歸 135.7 liveness 台帳 ④驗收 Walkthrough＋Architecture delta ⑤除錯原生全套 ⑥結案 Walkthrough 一步一弧＋M3 delta；user override 永遠可用）。**門禁句：渲染前自問消費者是誰、時刻是哪個、理解層在哪（0919 外部收割——L0 實作／L1 架構／L2 問題模型；user 注意力 L2↑、L1＝人機溝通 vocabulary 不全外包）——答不出就不跑。**自動化選型須待 AC#4 dogfood 帶回誤選成本證據後另行評估
☐ #4 AIR-135 自身至少 dogfood 一次 entry 或 exit Align，驗證 human 能快速指出「AI 理解與我的意圖哪裡不同」而非只看漂亮圖。**聯合 dogfood**：與 135.2 AC#5 共用同一投影產物（同一 artifact 同時滿足本 AC entry／exit Align 驗收與 135.2 verdict 裁決呈現）；dogfood 驗證含 exit evidence→view 的可追溯鏈——每個 exit evidence 必能指向對應 Code Lens 呈現物或明確標註不需呈現；**entry Align checksum 一問（0919 外部收割）：六欄視圖一屏可掃（低信心假設高亮＋預算數字行），user 30–60 秒內能答「AI 誤解我了嗎」——human/AI checksum 的視圖形態，載體即 M1／entry 視圖不另建文件**
