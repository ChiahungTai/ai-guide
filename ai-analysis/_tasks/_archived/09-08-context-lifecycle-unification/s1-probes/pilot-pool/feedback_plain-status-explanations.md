2026-09-03 報告 memory 截斷距離時用了五行「觸線順序」排序表（線名/現況/距離三欄），user 直接退回：「你剛寫的我看不懂」「……是啥？」「一次講清楚」。

**Why**：緊湊表格假設讀者已持有欄位語境（什麼是 gate、哪條是誰的線）；user 要的是先有骨架再有名詞——多行排序表把五個未定義名詞同時拋出，認知負載瞬間爆表。

**How to apply**：機制/狀態類解釋給 user 的排序——①油表式百分比＋一句白話結論（「離真的截斷還遠，因為我們自己的煞車線擋在前面」）；②比喻或分層圖（寫入端→索引端→harness 端）；③使用者自己問到的技術名詞才展開定義（「generator 硬 gate 18,500 是啥」→ 當條目答）。緊湊表格留給已定義名詞的橫向對照（如雙端語義表），不用於「距離/餘裕」敘事。

**同日增補（清單條目面）**：內部縮寫術語寫進「給 user 看的待辦清單」同樣會被問——「bundle 90% WARN（減量弧候選）、at-skill miss 教訓 codify 這是啥」。待辦/佇列清單呈現時每條自帶一句白話標註（或把背景觀察項獨立成段說明），縮寫只在該 session 已向 user 定義後才可複用。

**同日增補（機制解釋的第三層＝具體走查）**：解釋 desc 截斷機制時抽象表述兩次被退（「這件事有意義嗎」「不懂？121 為何要被截？」），第三次用具體走查才落地：單一案例從輸入到後果走一遍（121 字 desc→檔案完好→索引行截到 99+…→session 只看索引→搜被截尾的觸發詞→miss）。**How to apply**：白話結論＋比喻仍被退時，下一步不是再換比喻而是給 worked example——一個具體案例端到端走查，讓 user 在案例裡自己看見每個名詞的位置；機制因果鏈越長（≥3 環）越必須走查形態。

**09-05 增補（口語壓縮/自創代號面）**：收尾摘要一句「跟 DRAFT-12 說一聲就能把那個 149K 的 monster 收掉」被 user 問「這是啥」——自創代號（monster＝某記憶條目檔名）、內部編號（DRAFT-12）、口語動詞（說一聲＝promote 指令）三層壓縮疊在一句，user 無從解碼。**How to apply**：收尾/摘要句中的每個指涉物要嘛自帶一行白話展開（檔名＋它是什麼），要嘛用可執行的具體動作表述（「跑 `backlog draft promote DRAFT-12`」）；「說一聲/那個東西」級口語代換只在自己剛定義完的同一則訊息內可用，跨訊息收尾一律重新展開。

**09-07 增補（自創弧名簡稱面——任務有完整來源也一樣炸）**：commit 確認請求裡一行「mosaic handoff memory-audit 弧（一檔）」，user 問「這啥」——該任務是 user 一小時前**親自貼 handoff 工單交代**的（固化 mosaic cluster merge 兩條教訓進 memory-audit skill），名詞全是真詞、無縮寫無代號，但「handoff 弧」是 AI 自創的組合命名，切斷 user 對自己任務的識別。**How to apply**：對 user 複述任務用任務原始內容（做了什麼、改哪檔、來源是哪份工單），不用自創弧名/分類簡稱指涉——user 的識別鍵是他交代任務時的語言，不是 AI session 內部的工作分組名。
