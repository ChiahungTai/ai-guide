為什麼（本弧賭注）

EP 真正賭注不是 agent 數量而是分發紀律
  • 全生命週期 execution contract——開卡→EP 規劃→build→review→post-build→commit 每段必有一行可解析、可啟動、可回收、可驗收的 contract（stage→owning orchestrator→registry name→tier→harness registry→artifact→failure fallback）；「dispatch 給適合的執行者」含主 session——判斷密集段（EP 規劃／judge／post-build 編排／commit consent）不 agent 化（AIR-24 分工律）
