EP 全文

同一角色，不該綁死執行環境

問題不是少八個 Claude agent，而是 role、harness、model 三個決策混成一層
目前

2 個 reviewer 有 shared source；8 個角色只存在 ZCode registry。模型 pin、工具差異與角色正文一起演化。

目標

10 個 role 共用 neutral source；兩個 harness registry 都是可重建投影；模型由 requirement × provider 表解析。

不改

role names、AIR-24 主 session 裁決、real-file registry、Luna 排除與 external bridge redlines。

三層正交結構

ownership 單向：role source → projector → registries；dispatch 先 harness，再 provider/model
Agents role × harness × provider architecture↗ 全屏

四個可結算段落

先立權威語義，再搬 ownership；consumer 最後切換，runtime acceptance 單獨收尾
段落產物主要 gate
S1 計畫中routing tables＋harness matrix＋work-order role contract3×5 provider cells、AIR-24、Luna／vision constraints
S2 計畫中roles/＋pure projector＋兩 registryatomic 10/2/2→10/10/0、check zero-write、legacy adoption

S4 計畫中runtime evidence＋closeoutZCode 3-role sample、Claude 10+1 named-agent L4

最容易出錯的地方

EP review 已抓出並回寫 migration collision、frontmatter 失效與 Scenario traceability
  • 首次 adoption：現存四個 reviewer copies 無 marker；只能在 exact-bytes 等價時收編，不能直接覆寫。
  • 可載入格式：第一行必須是 YAML fence，target fields 留在 frontmatter，marker 放 closing fence 後。
  • 清除 blast radius：只刪 marker-owned stale outputs；unmarked fork 保留，同名衝突 loud failure。
  • 證據分級：Claude 10+1 是本機 L4；CC Agent tool 與 external runtimes 是 docs＋first-real-usage，不高報。
code-reality projection 目前仍有 baseline stamp mismatch；所有 projected edges 都是提案宣告，實作後須重建 index 才能升格為現況證據。
