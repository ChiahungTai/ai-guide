為什麼改

痛點→決策：branch 是唯一被 harness／VSCode 恆顯的 git 狀態＝免費 ambient UI
  • 痛點（mosaic 主場）：三個 VSCode 視窗＝三個 worktree（main/v2/warrant），branch 顯示的是線名——看得到線，看不到「這條線現在做到哪張卡」。
  • 決策：卡開工時 checkout 以「線縮寫＋卡號」命名的 branch（如 lab-77）——三視窗一眼讀出線＋卡。建卡不開 branch（建卡是承諾，開工才是動工）。
  • 附帶收益：git diff warrant..lab-77＝整卡機械邊界（跨 session review 用）；探索失敗刪 branch 即整卡丟棄，線零污染。
  • 為什麼不是每卡 rebase／merge：收尾走既有 /rebase 兩步（rebase onto 線 → 線 merge --ff-only 吸收）——純直線歷史、無 merge 氣泡，trunk-based 正統。
  • 業界對照：ticket-ID branch naming（Atlassian/Graphite 標準）＋ AI-era branch-per-task 共識（Anthropic --worktree、Kempé、Osmani）。
