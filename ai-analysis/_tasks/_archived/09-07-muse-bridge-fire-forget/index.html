痛點

長跑 muse 轉發（10-30 分鐘）以「caller session 掛背景 Bash 等 exit」為預設——每次轉發綁死一個 session / concurrency slot；N 個並行任務＝N 個 session 被佔。

解法

fire-and-forget：bridge 內建 task --background（detached worker＋ledger 持久化）提交後 jobId 秒回、session 釋放；事後任何 session 以 wait/show 跨 session 認領。

證據

bridge 0.2.5 源碼逐行驗證（detached/unref、ledger、wait 124 語義）＋兩端 hooks.json 實測差異＋Muse 本身諮詢確認形態（fire-and-forget＋late-collect）。

fire-and-forget 收法

收法階層——決策樹新形態（單一源：model-routing skill「完成回報收法」節）

決策樹頭形態（長跑 >10min）

  • 提交：muse task --background（長 prompt 用 --prompt-file）→ jobId 即回 → caller 結束 turn 釋放。
  • 晚收：wait <jobId>（有界 timeout 迴圈，起點 5min）或 show 認領——ledger 持久化於 workspace .muse-bridge/。
  • 多工複用：一個 session 持 N 個 jobId 統一掃（runs --json sweep）；並行 quota＝同 5h window 加總，實用並行 2-3 長任務。

兩端 SessionEnd 差異（能否跨 session 認領的分水嶺）

  • ZCode 端：plugin hooks 不執行（config 無掛載）→ detached worker 跨 session 存活，fire-and-forget 完整可用。
  • CC 端：SessionEnd hook 殺 running job 進程樹＋標 interrupted → holder session 必須活著，fire-and-forget 限縮為 session 內釋放 turn。
晚收陷阱（Muse 諮詢收編）：wait 用有界迴圈勿單一大 block；stop／清理前先 show／export（ledger GC 會吃證據）；委派工單設計成冪等；jobId 持久化在 ledger 不依賴提交 session context。
