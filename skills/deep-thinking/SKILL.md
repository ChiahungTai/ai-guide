# Deep Thinking — 深層思考框架（輸出格式與深層論證）

> 本 skill 是 `rules/design-thinking.md` 的 on-demand 深層載體：rule 端保留 always-on 核心（兩層思考強制、決策分級、架構三視角）；本檔承載輸出格式模板、思維框架圖、關鍵問題清單、程式碼查證細則與執行自檢清單。

## 思維框架圖

```
第一性原理（向下分解）                  第二層思考（向前追蹤）

1. 追溯基本問題 → 本質需求是什麼？不可妥協的約束？
2. 拆解到基本元素 → 基本組件與本質職責
3. 從基本原理重構 → 最佳方案？本質權衡？
4. 驗證假設 → 查證事實，根據證據調整
                                  ↓
5. 追蹤連鎖後果 → 「接下來會怎樣？」至少追蹤兩層（強制）
6. 評估完整影響 → 負面後果可接受嗎？需要重新分解嗎？
                                  │
                       後果不可接受 → 回到步驟 1 ┘
```

**步驟 5-6 是強制的**，所有決策都必須追蹤至少兩層後果。

## 關鍵問題

**第一性原理層（本質是什麼？）**
- **0. 讀者是誰**（這份文檔/UC/架構的讀者是誰？帶著什麼問題來讀？讀完應該能做什麼決策？——**必須在任何分析之前先回答**）
- 1. 本質需求（必須做到什麼？不可妥協的約束？）
- 2. 為什麼需要（解決什麼本質問題？沒有它會怎樣？）
- 3. 權衡（每個選擇用什麼換取什麼？）
- 4. 驗證（什麼事實會推翻這個設計？）

**第二層思考（接下來會怎樣？）**
- 5. 第一層後果（直接影響）
- 6. 第二層後果（第一層影響又導致什麼）
- 7. 如果我是錯的（最壞情況？可以逆轉嗎？逆轉成本？）

## 輸出格式

```markdown
## 深層思考分析

**本質需求**: [必須做到什麼？不可妥協的約束？]

**基本元素拆解**: [基本組件與本質職責]

**從基本原理推導**: [最佳結構？本質權衡？]

**驗證**: [如何驗證？什麼事實會推翻？引用來源：路徑:行號]

**連鎖後果追蹤**:
- 第一層後果：[直接影響]
- 第二層後果：[連鎖效應]
- 負面情境：[如果錯了會怎樣？]

**決策類型**: 單向門 / 雙向門
```

## 程式碼查證與連鎖後果

- **查證**：專案程式碼直接讀取源碼；套件源碼從 `.venv/lib/python*/site-packages/` 讀取確認實際行為；用具體路徑（如 `.venv/lib/.../main.py:122`），不憑記憶
- **連鎖後果追蹤**：修改 A 模組 → 依賴 A 的 B/C/D 受影響嗎？→ B 的下游消費者受影響嗎？新增抽象層 → 減少什麼複雜度？引入什麼認知負擔？改名/重構 → 所有引用處更新？文檔同步？下游斷裂？
