# Deep Thinking — 可查證的決策

先辨識要解決的問題與不可妥協的約束，再以證據比較選項及後果。總綱見 [design-thinking rule](../../rules/design-thinking.md)；架構決策同時使用 [arch-thinking](../arch-thinking/SKILL.md) 的判準。

## 入口：對準行為與決策

- **使用者**：誰使用被設計的東西，要完成什麼行為？文件或 skill 的使用者也可能是 LLM。
- **產出消費者**：這次分析給誰，讀完要作什麼決策？沿用呼叫端已指定的受眾與格式。
- **成功條件與範圍**：必須成立的行為、invariant、限制，以及本次可改與不可改的範圍。已有明確答案就引用，不重問使用者。

## 決策流程

第一性原理對應問題、約束、事實與選項的拆解；第二層思考對應直接影響之後的消費者／invariant。這些是檢查角度，不要求固定篇幅或另交一份推理過程。

1. **拆解問題**：說明現況為何不足、哪個責任或約束造成問題；先查既有機制，避免把提議的解法當成需求。
2. **分開事實與假設**：已查證事實附來源；推測寫成假設。優先查「若答案相反，推薦會改變」的未知，不先擴張成全系統調查。
3. **比較可行選項**：必含「不做（維持現況）」與「刪除既有」兩個基準評估——「刪除既有」無相關既有標的時明列 N/A、存在但不可刪時明列排除理由；再列最接近的可行替代。若現況違反硬約束，明列排除理由。只比較會影響選擇的行為、成本、依賴與風險，不為湊選項造方案。
4. **查直接與間接後果**：沿「變更 → 直接改變的行為或責任 → 受影響消費者或 invariant」追蹤。每個關鍵因果連結附證據或假設；不能只寫「更乾淨 → 更好維護」。
5. **檢查錯誤情境與可逆性**：哪個事實會推翻推薦？選錯會損害什麼？程式碼可回滾不代表已寫入資料或外部動作可逆；列出必要的回復條件。
6. **收斂**：推薦一個方案，交代取捨、未驗證項與改判條件。影響選擇的未知尚未解決時，給有條件建議及下一個查證動作，不宣稱已驗證。

## 深度與停止條件

每次決策都檢查直接與間接影響；展示深度依實際風險與呼叫端需求調整。

- 局部、可逆、契約未變：針對已識別的消費範圍查證，以簡短摘要交付。
- 跨 context、共用契約、state/invariant、外部副作用，或存在會改變推薦的未知：展開相應消費路徑與失敗情境，直到能選擇或明確指出阻塞證據。
- 在已查範圍未識別間接影響時，寫「在此範圍未識別」及查證範圍；不編造第二層故事，也不把它外推成全域無影響。
- 成功條件可判、選項可比較、關鍵因果有依據且沒有未處理的改判未知，即停止擴張。其餘不影響本次選擇的問題另列，不混入完成條件。

## 交付契約

交付**決策摘要**，不用展示內部逐步推理。將以下內容放入呼叫端既有段落或 finding 欄位；無指定格式時依此順序組織，簡單決策可合成一段：

- **目的**：使用者行為、產出消費者要作的決策、成功條件。
- **依據**：影響選擇的事實／假設，含來源及未驗證處。
- **選擇**：推薦方案、現況／替代方案的取捨。
- **後果**：直接與間接影響、錯誤情境與回復條件。
- **改判條件**：什麼證據會改變推薦；若仍缺，下一個查證動作是什麼。

## 查證與自檢

專案行為查實際 source/runtime；套件行為查當前使用的安裝版本或 fork，不能用 upstream 文件替代本地差異。符號查詢依 [symbol-query-routing](../../rules/symbol-query-routing.md)，證據強度依 [acceptance-evidence](../acceptance-evidence/SKILL.md)。結構圖、文件與測試各自只證明其覆蓋範圍。

交付前確認：回答了真正的行為問題；事實與假設分開；推薦相對現況有理由；後果有具體受影響者；未查到沒有寫成不存在；改判與回復條件可操作。檢查結果融入摘要，不再重複一份自檢表。
