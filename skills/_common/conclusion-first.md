# 結論先行——人類面報告輸出原則

> 適用：產出給人類判讀的報告——`/debrief`、`/illustrate`、`/smell-detector`、deep-work 完成報告等 viewport 命令與完成報告。LLM 執行鏈產出（EP、findings、code）不適用——命令受眾二分不變。

**人類可讀產出先結論／先人話，id／代碼／術語降為附註**：報告第一句回答「做了什麼／結論是什麼」，講行為與影響；卡 id、符號、路徑、術語縮寫不當主語——需要時放括號附註或末段索引。

❌ 錯誤：「AIR-142 落地 done；digest=c0087da3f8b59198；四檔 marker 已更新」
✅ 正確：「報告慣例改好了——以後給你的報告先講結論、代碼出處放附註（AIR-142；動 debrief/illustrate/smell-detector/deep-work 四檔＋共用檔）」

💡 原理：人類 viewport 補的是方向判讀（direction >> quality）；id／代碼堆疊迫使讀者自己反解意圖，等於把方向判斷的負擔丟回給人。真實案例：corrections 週報溝通糾正群——「要講做啥，不要只有id」「講人話」「不要一堆代碼」。

`/debrief` 七段輸出合約（倒金字塔）是本原則的既有正典實例。
