# 股票分析框架

> **載入時機**：分析個股或市場走勢時按需載入。通用深層思考框架（第一性原理 + 第二層思考）見 design-thinking rule／deep-thinking skill，本 skill 是其股票領域的具體應用。

## 分析必備視角（由下而上，每一層都必須經過）

### Layer 1（必備）：經典技術分析

所有股票分析必須先從經典技術分析理論出發，作為判斷的基礎框架：

- **Dow Theory**：主趨勢/次趨勢/日間波動三層結構、量價確認、趨勢持續直到明確反轉信號
- **Elliott Wave**：推動波（5 波）/修正波（3 波）結構、Fibonacci 比率（0.382, 0.5, 0.618, 1.618）
- **Wyckoff**：累積/markup/distribution/markdown 四階段、供需分析、Composite Operator 行為
- **Darvas Box**：箱型整理突破、量價配合確認、向上突破買進、向下跌破停損
- **Bollinger Bands**：均值回歸vs趨勢延續判斷、頻寬收縮（squeeze）預示突破、價格觸帶非訊號需搭配其他指標
- **Support/Resistance**：關鍵價位（前高前低、整數關卡、缺口）、支撐阻力互換
- **Volume Analysis**：量先價行、量價背離、OBV、累積/派發
- **Trend Analysis**：高點低點關係、趨勢線與通道、趨勢的三種規模

**為什麼經典 TA 必須先於量化指標**：經典理論提供的是**市場結構的解釋框架**（為什麼會這樣走），量化指標提供的是**數值化描述**（目前數值是多少）。先有解釋框架，數值才有意義。RSI=75 在強趨勢中（Dow Theory 主趨勢向上）可以長期維持，不代表超買。

### Layer 2（疊加）：量化/系統觀點

經典 TA 框架建立後，疊加系統計算的指標和結構（跨專案時替換為當前專案的對應模組）：
- 當前專案的指標模組（如 RSI、MACD、ATR 計算層）
- 當前專案的結構模組（swing/leg/trajectory 類結構節點）
- 當前專案的特徵工程模組（spec-driven 特徵管道）

### Layer 3（整合）：第二層思考

用第二層思考整合多維度分析。**核心動作：列出各技術分析理論之間的共識與歧異，讓用戶判斷**：

- **共識點**：哪些理論對當前走勢有相同判斷？（共識越強，可靠性越高，但也意味著已被定價）
- **歧異點**：哪些理論對當前走勢有不同判斷？歧異在哪裡？（歧異處是風險，也是機會）
- 「這個價位反映了什麼預期？什麼事實會打破這個預期？」
- 「如果這個判斷是錯的，最大損失是什麼？我接受嗎？」
- 「風險的悖論：所有人都認為安全時最危險，所有人都認為危險時可能最安全」

## 輸出要求

股票分析結論必須包含「各理論共識/歧異對照」段落，格式：

```markdown
### 理論共識與歧異
| 理論 | 判斷 | 信心 | 依據 |
|------|------|------|------|
| Dow Theory | 偏多 | 高 | 主趨勢向上，量價配合 |
| Elliott Wave | 偏空 | 中 | 可能處於第 5 波末端 |
| Bollinger | 中性 | 低 | 頻寬收縮，方向未明 |
| Darvas Box | 偏多 | 中 | 箱頂突破確認 |
| **共識** | 偏多（3:1） | — | 主要理論偏多，但 Elliott Wave 歧異需注意 |
```

## 事件研究與回測量測紀律

> **視角定位**：上方三層是「怎麼判斷走勢」；本章是「回測與事件研究怎麼量測才不失真」——模擬語意、單位、時間點、檢定界線。判讀面（怎麼看圖）見 [kbar-form-analysis](../kbar-form-analysis/SKILL.md)；畫圖選型、vision 契約、數字↔視覺雙向驗證與人類板設計見 [diagram-selection](../diagram-selection/SKILL.md)。材料源：mosaic MOS-42 現增事件弧（2026-09-05 心得稿）。

### 回測模擬語意（trailing 紀律類）

- **進出場紀律必須模擬「可回補」**：trailing MA 出場後要能再進場。single-shot（跌破一次永離場）會把大漲案報酬 med 砍到近零——贏家普遍在主升段前先跌破短均線洗盤，洗盤→主升是常態路徑（低點停留極短、主升段隨後啟動）
- **「站上 X 才買」單獨無防護**：站上短均線幾乎人人都會在極短時間內觸發（含後來崩跌的）——防護必須在出場端（破線賣）而非進場端
- **事後確認進場吃不到溢價**：等確認訊號才進場，報酬 med 大幅縮水——邊際都在事前特徵，事後確認一路是虧的（V 訊號/低點確認/強度確認三次獨立實證同一結論）
- **量測面**：窗末仍持倉時的成本估算用 per-case `ceil(switches/2)`，不是 `switches/2`

### 單位單一源（管線防 bug 鐵律）

- **管線內部／CSV 存檔一律 fraction、顯示時才 ×100**——三者分層，不得混用
- 實證 bug 形態：CSV 存百分比值卻拿 fraction 門檻比較（篩選差兩個數量級）；display ×100 把負報酬顯示成荒謬值
- **跨 CSV join 是單位／撞鍵溫床**：中繼產物每多一跳，單位口徑與複合鍵（如 code/year 跨年撞鍵）風險各乘一次——多腳本串接收斂成單一源後曾回收多案漏失樣本
- **複權口徑同律**：統計用 adjusted（`adj_close` 欄）、判讀用 raw——讀錯欄會得「調整是 no-op」的假象

### point-in-time 紀律（特徵工程）

- **基本面特徵用公告日錨**：`announcement_date <= 錨點日`（月營收次月 10 日前公布），用資料日期欄而非月份推斷
- **環比必須季節調整**（mom_sa = MoM − 同日曆月全市場中位數）：否則全市場季節結構會讓門檻量測實際量到「事件窗落在幾月」
- **事後特徵禁止進事前分組**：窗內低點位置/dip 深度等事後特徵可作描述與出場規則素材，禁作進場訊號（base rate 反覆否決）
- **事件資料 guard**：同 code 兩個 event_year 掛同一組日期（多年事件鏈互相覆蓋）——機械 guard 攔截

### 探索↔正式化界線

- **幾十次 in-sample 切分無多重檢定控制＝每格都可能 data snooping**——報告顯式分離「探索性/確認性」結論
- **預註冊式驗證**：規則文字凍結（gates/進出場寫死）→ 未參與探索的新樣本重驗——倖存與陣亡訊號如實分欄，不隱匿陣亡
- **年度切分是最低成本的偽 walk-forward**：「相對報酬/防禦型」（多數年份正、負年份虧損減半）與「年年賺」是不同宣稱，分開講
